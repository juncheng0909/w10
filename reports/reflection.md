# Reflection：從真實問題修正流程

日期：2026-11-14。以下反思依據 ingest log、workflow-runs.jsonl 與 browser-attempt 紀錄撰寫，不宣稱發生未實測的故障。

## 來源整理遇到的問題

Williams College 講義的 GC 段落在位元翻轉方向上有文字矛盾。若直接將來源改寫成圖，很容易把矛盾一併帶入教材。本次保留其 FTL / GC 教學價值，但不使用位元方向說明，改以 SNIA、Samsung、KIOXIA 交叉確認 erase-before-write 與 Page/Block 的操作粒度。

Samsung 與 KIOXIA 的 Block 大小範圍不同。本次不選其中一組數字冒充通用規格，而把圖縮成四頁 Block 並標明是教學模型。這讓初學者能看懂搬移與擦除，同時保留產品差異。

Red Hat 來源屬 RHEL 7。本次只採用 discard 的通知語意與 TRIM 後讀取行為存在差異的事實。沒有把舊系統指令寫成現代作業系統的設定建議。TRIM 不保證立即擦除或安全抹除，是根據通知語意與 Block erase 規則的明確推導。

## 實際檢查與修正

1. 第一輪自動關卡在沒有實測瀏覽器報告時拒絕發布。這是有效阻擋，不是內容錯誤。來源、Wiki 與技術模型已通過。
2. 第一次瀏覽器連本機預覽逾時。重新以已授權網路存取啟動預覽後成功，沒有把連線失敗記成版面測試通過。
3. 桌面原版的 16:9 canvas 加上 header / navigation 後，高度達 852px，超過 720px 視窗。手機切頁也保留原本捲動位置。只修改 templates 的可用高度與切頁捲動行為。
4. 第二次檢查發現 GC 三階段圖以及四題答案全展開時會碰到來源區。原先只比 scrollHeight / clientHeight，抓不到子元素重疊，因此加做 footer 與內容 bounding rectangle 的交叉檢查。接著縮小桌面 GC 圖的留白與展開答案的段落間距，沒有刪改技術敘述。
5. 排版加入 `data-slide` CSS 選擇器後，測試器原先只數字串，誤判有 18 頁。修改為只計算 `<section>` 的屬性。這是測試器錯誤，不是新增了投影片。原始失敗與後續通過皆保存。
6. 另外在暫存副本故意移除來源、破壞證據、刪除逐頁稿、改 HTML 雜湊，確認各關卡退回位置與最多三輪上限。這些是明確標示的故障注入測試，沒有混成實際教材失敗。

## 最終結果與限制

實際檢查 1280×720、390×844、360×800，各 12 頁。桌面不再超出視窗，三種尺寸皆無水平溢出與引用區重疊。第 12 頁四題答案全部展開也通過。手機長內容採垂直閱讀，這是明確的 responsive 設計。

技術模型驗證了有效頁搬移前不能擦除、mapping 指向新版本、TRIM 邏輯失效不會直接將 NAND 頁變成已擦除，以及同尺度 WAF 計算。模型只是針對教材不變條件的參考程式，不是實際 FTL 或 NAND 模擬器。程式能確認文字與證據鏈一致，仍需要人工判讀來源。

目前沒有實體 SSD 效能量測、跨瀏覽器認證或真實手機硬體測試。瀏覽器報告以 HTML SHA-256 綁定，HTML 更新後必須重測；報告檔並非防偽系統，不能取代誠實紀錄。

## Graph 是否修改

Graph v1 的節點與回退邊未修改，因此沒有虛構前後差異。實際調整的是 HTML 排版、功能與檢查器的判定條件。初版圖保存在 workflow/graph-v1.mmd，執行歷史保存在 reports/workflow-runs.jsonl。若未來修改 Graph，應新增 v2 與 diff，不覆寫 v1。
